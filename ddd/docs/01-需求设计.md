# 需求设计（Requirement Design）

## 1. 项目概述（Bounded Context）
一个轻量级**电商订单管理**域。系统为用户创建、提交、履约订单，并围绕"订单"建立统一的领域语言
（Ubiquitous Language）。本示例只覆盖订单的生命周期管理，以演示 DDD 落地。

## 2. 领域语言（Ubiquitous Language / Glossary）
| 术语 | 含义 | DDD 名词 |
| ---- | ---- | -------- |
| 订单 Order | 一次购买行为聚合根 | Aggregate Root |
| 订单项 OrderItem | 订单里的一个商品条目 | Entity |
| 金额 Money | 以"分"为单位的不可变金额 | Value Object |
| 订单号 OrderId | 订单唯一标识 | Value Object |
| 客户号 CustomerId | 下单客户标识 | Value Object |
| 订单状态 OrderStatus | 状态机，式流转 | Value Object / Enum |
| 收货地址 Address | 不可变地址 | Value Object |

## 3. 核心用例（Use Cases / 应用服务）
1. 创建订单：给定客户与收货地址，返回新订单号。
2. 追加订单项：向订单添加一个商品（数量、单价）。
3. 移除订单项：从订单删除一个商品。
4. 提交订单：订单进入"已提交"状态。**提交后不可再增删订单项**。
5. 取消订单：取消未发货的订单。
6. 发货 / 完成订单：推进状态机。
7. 查询订单列表与总额。

## 4. 核心业务规则（Domain Invariants / 不变量）
- **INV-1**：订单至少包含 1 个订单项；空订单无法提交。（粒径：聚合内一致性）
- **INV-2**：订单项数量必须 > 0，单价必须 ³ 0。
- **INV-3**：订单总金额 = Σ(单价 × 数量)，且 ³ 0（由聚合计算，不做存储冗余，避免不一致）。
- **INV-4**：状态必须按合法状态机流转（见下）。
- **INV-5**：已提交/已确认后的订单，`addItem`/`removeItem` 必须被拒绝。
- **INV-6**：已发货订单不能被取消；已取消订单不可再流转。
- **INV-7**：金额使用"分"作为最小单位（`long long`），杜绝浮点误差。

## 5. 订单状态机（Domain State Machine）
```
        +--------+
        | Created|--add/remove--> (可变更条目)
        +---+----+
            | submit
            v
        +----------+
        | Submitted |            // 锁定条目
        +----+-----+
             | confirm
             v
        +----------+
        | Confirmed |
        +----+-----+
             | ship
             v
        +----------+
        | Shipped   |            // 此后不可取消
        +----+-----+
             | complete
             v
        +----------+
        | Completed |  <terminal>
        +----------+

  Created/Confirmed ---cancel---> Cancelled (terminal)
```
合法转移表（`OrderStatus::canTransitTo(prev,next)`）：

| prev | next |
| ---- | ---- |
| Created | Confirmed / Cancelled |
| Confirmed | Shipped / Cancelled |
| Shipped | Completed |
| Completed | （终态） |
| Cancelled | （终态） |

注：示例中 `submit` 直接进入 `Confirmed` 以简化；若需更细粒度可增加 Submitted 状态。

## 6. 领域事件（Domain Events）
聚合在关键动作时发布事件，交由应用层/基础设施订阅（本示例演示同步派发）：
- `OrderSubmitted(orderId, total)`
- `OrderCancelled(orderId, reason)`

## 7. 角色人 / 非功能约束
- 不变量校验必须在**领域层**做（聚合方法内自检），而非散落应用层。
- 对外返回**业务错误码**（`DomainError`），跨越层边界不依赖异常（使用 `Result<T>`）。
- 仓储以接口定义在领域层（依赖倒置），具体实现在基础设施层。
